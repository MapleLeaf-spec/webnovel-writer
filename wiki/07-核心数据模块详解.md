# 07 · 核心数据模块详解

> 全部位于 `webnovel-writer/scripts/data_modules/`。本章按"合同 → 提交 → 投影 → 状态/索引"主链顺序讲解关键类与函数。

## 1. 合同引擎：story_system_engine.py

**核心类**：`StorySystemEngine`

| 成员 | 签名/说明 |
|------|----------|
| `build(query, genre, chapter, chapter_directive=None) -> dict` | 主入口：输出 `master_setting`（MASTER_SETTING 契约）+ `chapter_brief`（CHAPTER_BRIEF 契约）+ `anti_patterns` |
| `_route()` | 按 `题材与调性推理.csv` 路由：关键词 → 显式题材 → 文本推断三级 fallback |
| `_collect_tables()` | 经 reference_search 检索基础/动态表 |
| `_load_reasoning()` / `_apply_reasoning()` | 按 `裁决规则.csv` 的冲突裁决优先级 + `_combined_rank_score()` 加权排序 |
| `_rank_anti_patterns()` | 按毒点权重排序 |
| `is_placeholder_query(query) -> bool` | 占位 query 检测 |
| `StorySystemRoutingError(ValueError)` | 路由异常 |

模块级：`is_placeholder_query(query)`。

**陷阱**：query 含占位文本时拒绝生成合同（plan Step 10 与 prewrite gate 均依赖）。

## 2. 章节提交链：chapter_commit_service.py

**核心类**：`ChapterCommitService(project_root)` —— 提交事实构建 + 派生读模型投影分发的领域服务。

| 方法 | 说明 |
|------|------|
| `build_commit(chapter, review_result, fulfillment_result, disambiguation_result, extraction_result) -> dict` | 四份 artifact pydantic 校验；判定 `accepted/rejected`（blocking_count>0、missed_nodes、pending 任一 → rejected）；规范化 accepted_events；组装 payload（contract_refs / outline_snapshot / projection_status=pending） |
| `persist_commit(payload) -> Path` | 写 `.story-system/commits/chapter_NNN.commit.json` |
| `apply_projection_writers(payload)` | `EventProjectionRouter.required_writers()` 挑 writer → 逐个 `apply()` → `projection_status` → `append_projection_run()` 落账本 |
| `apply_projections(payload)` | accepted 时：EventLogStore 双写事件 → AmendProposalTrigger 修正提案 → `apply_projection_writers` |

## 3. 提交 Schema：chapter_commit_schema.py

基类 `CommitArtifactModel(BaseModel)`：`validate_top_level_shape` 禁止 wrapper 包裹（兼容旧版嵌套写法由 `commit_artifacts.py` 处理）。

| 模型 | 关键字段 |
|------|----------|
| `ReviewResult` | `blocking_count: int` |
| `FulfillmentResult` | planned / covered / missed / extra_nodes |
| `DisambiguationResult` | `pending`（待消歧列表） |
| `ExtractionResult` | `accepted_events` / `state_deltas` / `entity_deltas` / entities_appeared / scenes / chapter_meta / dominant_strand / summary_text |
| `AcceptedEventInput` / `AcceptedEventsInput` | 事件输入 + `normalize()` |

模块级：`normalize_accepted_events(chapter, events)` —— 事件类型别名归一（`EVENT_TYPE_ALIASES`，如 `breakthrough→power_breakthrough`）。`commit_artifacts.py` 提供统一访问器：`extraction_result_from_commit` / `extraction_list` / `extraction_dict` / `extraction_text`。

## 4. 事件链

### 4.1 story_event_schema.py

`StoryEvent`（Pydantic）：`event_id` / `chapter(ge=1)` / `event_type`（10 种严格枚举）/ `subject` / `payload`。

### 4.2 event_log_store.py

`EventLogStore`：`write_events(chapter, events)` 双写（`events/chapter_NNN.events.json` + `index.db story_events` 表，`INSERT OR IGNORE` 幂等）；`read_events(chapter)`；`list_recent(chapter, limit=200)`；`health()` 双侧对账。

### 4.3 event_projection_router.py

`EventProjectionRouter`：类级路由表 `TABLE`（如 `character_state_changed → [state,memory,vector]`、`relationship_changed → [index,vector]`）；`route(event) -> List[str]`；`required_writers(commit_payload) -> List[str]`（rejected 仅 state；accepted 必含 state+index，再按 entity_deltas→index、summary_text→summary、事件类型并集扩展）。

### 4.4 override_ledger_service.py

- `normalize_override_record(...)`：覆盖记录规范化
- `ensure_override_ledger_columns(conn)`：增量补列（record_type/field/base_value/override_value/source_level/reason_tag）
- `AmendProposalTrigger`：`RULES`（仅 `world_rule_broken` 触发，target_level="master"）；`check(chapter, events)` → 生成 `AmendProposal`（`amend-{chapter}-{event_id}`）
- `persist_amend_proposals(conn, chapter, proposals)` → `override_contracts`（constraint_type="AMEND_PROPOSAL"、status="pending")

## 5. 状态双写：state.json + SQLite

### 5.1 state_manager.py

dataclass：`EntityState` / `Relationship` / `StateChange` / `_EntityPatch`。

`StateManager`（`enable_sqlite_sync=True`）：

| 分组 | 方法 |
|------|------|
| 读写 | `_load_state()` / `save_state()`（文件锁 + 原子写）/ `_sync_to_sqlite()` |
| 章节状态机 | `update_progress(chapter, words)` / `get\|set_chapter_status()`（单调递进 `chapter_drafted → chapter_reviewed → chapter_committed`，可 rejected） |
| 实体 | `add_entity` / `update_entity` / `update_entity_appearance` / `get_entity(s)_by_type/tier` |
| 记录 | `record_state_change()` / `add_relationship()` / `_record_disambiguation()` / `process_chapter_result(chapter, result)` |
| 导出 | `export_for_context()` / `sync_protagonist_from_entity()` / `sync_protagonist_to_entity()` |

### 5.2 sql_state_manager.py

`SQLStateManager(config)`：封装 IndexManager，接口与 StateManager 兼容——`upsert_entity` / `get_core_entities` / `get_protagonist` / `resolve_alias` / `record_state_change` / `upsert_relationship` / `get_relationship_between` / `process_chapter_entities` / `export_to_entities_v3_format` / `export_to_alias_index_format`。被 `migrate_state_to_sqlite.py` 使用（大字段迁移，防 state.json 膨胀）。

## 6. SQLite 索引：index_manager.py + Mixin

```text
IndexManager(IndexChapterMixin, IndexEntityMixin, IndexDebtMixin, IndexReadingMixin, IndexObservabilityMixin)
```

| Mixin | 关键方法 | 数据表职责 |
|-------|----------|-----------|
| *Chapter* | `add_chapter` / `add_scenes` / `record_appearance` / `get_recent_chapters` / `process_chapter_data` | 章节/场景/出场记录 |
| *Entity* | `upsert_entity` / `register_alias` / `record_state_change` / `upsert_relationship` / `record_relationship_event` / `build_relationship_subgraph`（可渲染 Mermaid）/ `update_entity_field` | 实体/别名/状态变化/关系图谱 |
| *Debt* | `create_override_contract` / `get_pending_overrides` / `get_overdue_overrides` / `fulfill_override` / `create_debt` / `get_active_debts` / `accrue_interest` / `pay_debt` / `get_debt_summary` | Override 契约 + 追读力债务 |
| *Reading* | `save/get_chapter_reading_power` / `get_pattern_usage_stats` / `get_hook_type_stats` / `save_review_metrics` / `get_review_trend_stats` / `save_writing_checklist_score` | 追读力 + 审查指标 |
| *Observability* | `mark_invalid_fact` / `resolve_invalid_fact` / `list_invalid_facts` / `log_rag_query` / `log_tool_call` / `get_stats` | 无效事实 + 工具/检索观测 |

`_init_db()` 建表；`_get_conn()` 上下文管理器。

## 7. 投影体系（5 个 writer + 账本）

统一接口：`apply(commit_payload) -> dict`，返回 `{applied, writer, reason/...}`。

| Writer | 类 | 落点 | 关键逻辑 |
|--------|-----|------|----------|
| state | `StateProjectionWriter`（+ `_LockedState` 锁上下文） | `state.json` | `_collect_state_deltas` / `_normalize_state_delta` / `_set_path`；伏笔 `_apply_foreshadowing`；三线 `_apply_strand_tracker`；字数 `_project_total_words`；accepted/rejected 都推进章节状态 |
| index | `IndexProjectionWriter` | `index.db` | `_upsert_chapter` / `_apply_scenes` / `_apply_appearances` / `_apply_state_changes`（`_state_change_exists` 去重）/ `_collect_entity_deltas` |
| summary | `SummaryProjectionWriter` + `append_summary_projection()` | `summaries/chNNNN.md` | 把 `summary_text` 写盘 |
| memory | `MemoryProjectionWriter` | 记忆库 | 委托 `memory/writer.py` 的 `MemoryWriter.apply_commit_projection()` |
| vector | `VectorProjectionWriter` | `vectors.db` | `_collect_chunks()`（`_event_to_text` / `_delta_to_text`）→ `RAGAdapter.store_chunks()` 异步入库（`_run_store_coro` 处理无事件循环场景） |

**账本 projection_log.py**：`projection_log_path()`（`.webnovel/projection_log.jsonl`）；`commit_hash()`（payload SHA-256）；`build_projection_run()`；`projection_status_from_run()`；`projection_run_failed()/pending()`；`append_projection_run()`；`read_projection_runs()`；`latest_projection_run()`。

**补跑 projections.py**：`retry_projection(project_root, *, chapter)` / `replay_projections(project_root, *, start_chapter, end_chapter)`。

## 8. 合同模型与运行时

| 模块 | 关键内容 |
|------|----------|
| `story_contract_schema.py` | `ContractMeta`（schema_version="story-system/v1"）/ `OverrideBundle`（locked/append_only/override_allowed）/ `MasterSetting` / `ChapterBrief` / `VolumeBrief` / `ReviewContract` |

## 11. 模块级依赖热点

被调用最多的共享依赖（改代码前必看）：

1. `config.py` —— `get_config(project_root=None)`：全项目配置唯一入口
2. `project_locator.py` —— `resolve_project_root()`：项目根解析
3. `security_utils.py` —— `atomic_write_json()` / `restore_from_backup()`：所有 JSON 写盘
4. `index_manager.py` —— 所有 index.db 读写
5. `commit_artifacts.py` —— commit payload 访问器
